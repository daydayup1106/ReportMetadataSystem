# 上线注意事项

## 1. 部署方式

本项目生产环境计划使用 `docker-compose` 部署。推荐做法是让应用和依赖服务通过 Docker 内部网络通信，而不是把 MongoDB、Redis 直接暴露到公网。

推荐服务间访问方式：

- Spring Boot -> `mongodb:27017`
- Spring Boot -> `redis:6379`
- Spring Boot -> `milvus:19530`
- Spring Boot -> `minio:9000`
- Spring Boot -> `embedding-service:8001`

这也是 `application-prod.yml` 当前的默认值来源。

建议使用：

- [docker-compose.prod.yml](D:/development/IdeaWorkspace/reportMigration/docker-compose.prod.yml)
- [.env.prod.example](D:/development/IdeaWorkspace/reportMigration/.env.prod.example)

---

## 2. 生产配置原则

- 启动时使用 `prod` profile
- 敏感信息全部走环境变量，不写死在配置文件里
- `application-prod.yml` 只负责生产环境覆盖项，不保存真实密钥
- 优先使用容器服务名通信，不依赖宿主机端口映射

建议设置：

- `SPRING_PROFILES_ACTIVE=prod`
- `ANTHROPIC_API_KEY=...`
- `MINIO_ACCESS_KEY=...`
- `MINIO_SECRET_KEY=...`
- `REDIS_PASSWORD=...`

如有需要也可以覆盖：

- `MONGODB_URI`
- `REDIS_HOST`
- `REDIS_PORT`
- `MILVUS_HOST`
- `MILVUS_PORT`
- `MINIO_ENDPOINT`
- `EMBEDDING_SERVICE_URL`

---

## 3. Redis 安全建议

- 不要把 Redis 直接暴露到公网
- 如果 Spring Boot 和 Redis 在同一个 `docker-compose` 网络里，Redis 不需要写 `ports`
- 必须配置密码或 ACL
- 只允许应用服务访问 Redis

结论：

改端口只能算弱安全措施，真正有效的是“不暴露公网 + 密码/ACL + 防火墙限制”。

---

## 4. MongoDB 安全建议

- 不要把 MongoDB 直接暴露到公网
- 优先只在 Docker 内网开放
- 生产环境应启用认证账号，不要匿名访问
- 如果使用副本集，连接串里应写完整副本集参数

---

## 5. MinIO 安全建议

- 必须修改默认账号密码
- 不要继续使用开发环境里的 `admin / admin123456`
- 控制台端口不要直接暴露公网，至少要加反向代理和访问限制

---

## 6. 应用层建议

- 生产日志级别保持 `INFO`
- 默认关闭 Swagger UI
- Actuator 只暴露必要端点
- 外部依赖地址和密钥都通过环境变量注入

## 8. 一句话原则

生产环境不要依赖“改端口就安全”，而是要优先做到：

`内网通信 + 环境变量注入 + 认证鉴权 + 最小暴露面`
